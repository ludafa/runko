## 这是什么

[上下文压缩（compaction）](../../terms.md)让**会话可以无限聊下去**。会话变长后，nimbo 把较早那段对话换成一条[摘要](../../terms.md)再喂给模型，从而把发给模型那份[模型上下文](../../terms.md)的体量压住。代价是：模型对较早的历史只保留摘要级记忆，但**界面上你能看到的完整历史一行不少**——压缩只动模型看的那份推导结果，不动你看的那份。

一句话：**长会话不再撞墙而死，换来的是模型对早期细节的记忆变粗。**

## 解决什么问题

chat 应用里一个会话是**无限期**的：一个会话绑一条分支，[沙盒](../../terms.md)休眠唤醒可以跨天续聊。会话足够长，就必然撞上模型的上下文上限。

在有本功能之前，撞上限的行为是 v1 的显式报错（`turn.failed` / `context_overflow`，见 [core/core-sdk/tech](../../core/core-sdk/tech.md) §4.8）——**会话到头即死**。compaction 把这条死路改成缓解：接近上限时自动把早期对话压成摘要，会话继续。

> 定位：compaction 是**缓解，不是保证**。真撞墙仍按 v1 的显式报错兜底（见下方「失败与降级」）。

## 谁用、怎么用

### 自动压缩（无感）

你什么都不用做。当一轮结束后模型回报的输入 token 逼近上限时，压缩**自动发生**，对话不中断。你唯一会注意到的是：时间线上出现一条「**已自动压缩上下文**」的分隔卡片，可展开查看这次摘要的全文。

### 手动 `/compact`（斜杠命令）

在聊天输入框里输入斜杠命令 `/compact` 主动触发一次压缩。可以附带指令，让摘要照你的要求来：

```
/compact 压缩，但保留所有文件路径和分支名
```

附带的指令会进入摘要生成的 prompt（并存档进这条压缩记录，便于事后查看当时是按什么要求压的）。

**约束**：一[轮（turn）](../../terms.md)进行中不能压缩。此时手动触发会被拒（提示稍后再试）——压缩只在轮与轮之间的边界发生。

### 对外 API（开发者视角）

手动触发对应一个 HTTP 端点：

| 端点 | 行为 |
|---|---|
| `POST /api/chat/sessions/:id/compact` | 请求体可带 `{ instructions?: string }`。空闲时受理并异步压缩；一轮进行中返回 **409**（turn 进行中，稍后再试）。 |

输入框里的 `/compact` 就是被前端拦截后转发到这个端点的。**触发这件事本身不进[账本](../../terms.md)**：手动 `/compact` 是一条 API 命令、不是对话消息，自动触发是内部决策——账本里只会出现压缩的**结果**（一条 compaction 记录），不会出现「谁在什么时候点了压缩」这条流水。

## 用户可见行为

- **自动压缩无感**：接近上限时自动发生，对话不中断；时间线上出现一条「已自动压缩上下文」的分隔卡片，可展开查看摘要全文。
- **手动 `/compact`**：输入框斜杠命令，可附指令。turn 进行中不可压缩（提示稍后再试）。
- **完整历史永远可回看**：压缩不影响时间线回放——被压缩的消息照常显示，分隔卡片只标记「模型上下文从这里起以摘要开头」。分隔卡片会区分这次是 **auto** 还是 **manual** 触发的文案。
- **失败静默降级**：摘要生成失败不打扰你，下一轮触发时自动重试；真撞墙时仍按 v1 显式报错兜底。

## 失败与降级

摘要生成是一次独立的模型调用，可能失败或超时。发生时：

1. **不写任何记录**、不打扰你，只在服务端记日志；
2. 下一轮再次触发时**自动重试**；
3. 如果在重试成功之前就真的撞上了上下文上限，退回 v1 的显式报错（`context_overflow`）兜底。

换句话说，压缩失败最坏也只是「没压成」，绝不会损坏会话或丢历史。

## 范围与非目标

本功能**明确不做**以下事情（这些是刻意划出去的边界，不是遗漏）：

- **memory / 长期记忆**：正交机制。压缩不往 memory 搬东西——账本本身就是无损归档，早期原文从没离开过账本。
- **context-editing 式细粒度清除**（单独清工具结果 / 推理块，不动对话骨架）：列 v2 观察项，等真实 token 构成数据再评估。
- **展示层压缩**：永远不做。界面看到的历史永远完整、可逐条回放。
- **turn 内压缩**：v1 只在 turn 边界压缩。单 turn 内步数撑爆上下文的场景由 `maxTurnsPerRun` 兜底，不归本功能。
- **search-history 工具**（让模型主动翻被压缩的旧账）：锦上添花，缓议。

减上下文的另一招——[外化（offload）](../../terms.md)（大内容落文件、上下文只留路径引用、需要时用工具读回来）——与压缩正交，是另一套机制，不在本功能范围内。

## 成功标准

- **压缩后能正常续作**：压缩后模型带着摘要继续干活——知道自己做过什么、文件在哪、接下来干什么（真机验证，见 [施工进展](./plan.md) 验收项 5）。
- **展示层零损失**：压缩后刷新页面 / 断线重连，时间线与压缩前**逐条一致**（e2e 验证，见 [施工进展](./plan.md) 验收项 7）。
- **推导正确性可离线证明**：不依赖真机，用离线断言覆盖「摘要在首、切点过滤正确、链式压缩只认最新、转换合法」（见 [施工进展](./plan.md) 验收项 1–4）。
