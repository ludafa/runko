# 停止本轮（使用手册）

> 相关：技术方案见 [tech.md](./tech.md)，施工进展见 [plan.md](./plan.md)。
> 依赖/延续：[chat 聊天 webapp](../../app/chat-webapp/feature.md)（[轮](../../terms.md)的驱动、[直播流](../../terms.md)、时间线渲染）· [中途插话与排队](../steer-and-queue/feature.md)（本功能补上它明确排除的那一项「硬打断当前轮」）· [UIMessage 单账本](../single-ledger/feature.md)（停止后账本照常收尾，不新增条目类型）。

这一份是**产品/使用视角**：解决什么问题、用户看得到什么行为、边界在哪。内部实现看 [技术方案](./tech.md)。

## 0. 一句话

agent 正在跑一[轮](../../terms.md)时，用户可以按**停止**把它叫停：当前这一轮立刻收尾、[待发队列](../../terms.md)一起清空，已经做过的事全部留在时间线上，下一条消息照常起新一轮。

## 1. 要解决的问题

现状（本功能之前）：一轮跑起来之后**没有任何办法叫停**。三个具体痛点：

1. **看出跑偏了也只能干等**。agent 理解错了需求、正在往错方向改一堆文件，用户唯一的选择是等它把这一轮跑完（可能几分钟、几十步），再发一条消息纠正。
2. **烧时间也烧钱**。一轮跑偏了还要跑完所有剩余 [step](../../terms.md)，每一步都是一次真实模型调用。
3. **界面上那个「停止」是假的**。前端 hook 里有一个 `cancel`，它只断开本浏览器标签的[直播流](../../terms.md)连接——服务端那一轮照样跑到底，刷新页面又全冒出来。它从来没接到界面上（没有任何按钮用它），因为接上去就是骗人。

## 2. 用户看得到什么

### 2.1 停止键就是发送键的流式形态

一轮**正在跑**时，输入框右下角那个发送键变成**方块停止键**（同主流聊天应用的姿态）。点它 = 停止本轮。

- 一轮**没在跑**时它还是发送键，行为与以前完全一样。
- 输入框**不禁用**——流式期间仍然可以打字：**Enter 照旧[排队](../../terms.md)**、**Alt/Option + Enter 或闪电按钮照旧[插话](../../terms.md)**（见 [中途插话与排队](../steer-and-queue/feature.md)）。停止键只是接管了那颗按钮的**点击**语义，没有拿走排队这条路。
- 点下后按钮进入「停止中」态（禁用），直到这一轮真的停下来为止——不会因为多点几下发出多次停止。

### 2.2 停止是真的停

按下停止后：

- 服务端**当前这一轮**被中止，不再进入下一个 step、不再有新的模型调用。
- **待发队列一起清空**（这是本功能的定案：「停止」= 全停，不是「跳过这一轮」）。排着的消息会从待发区消失，不会在这一轮停下后自己冒出来接着跑。
- 停止是**服务端行为**，不是这个浏览器标签的：换标签页、刷新页面、另一台设备打开同一个会话，看到的都是「已停止」。

### 2.3 停下来的时刻取决于 agent 当时在做什么

按下停止到真正停住，中间可能有一小段延迟——因为 agent 手上那件事要先收尾：

| agent 当时在做 | 停止如何生效 | 用户看到 |
|---|---|---|
| 模型正在输出文字/推理 | 立刻掐断这次模型调用 | 已经吐出来的那段文字**留着**，末尾标「已停止」 |
| 正在执行工具（如一条跑很久的 bash 命令） | 命令收到中断信号、秒级内收尾，该轮随即在下一个 step 边界停住 | 那次工具调用显示为被中断（红色错误态），后面不再有新动作 |
| 停在[审批卡片](../../terms.md)上等人裁决 | 该卡片按「拒绝」结掉，本轮随即停止 | 卡片落成「已拒绝」，末尾标「已停止」 |

一律**不会**出现「按了停止但它又跑了一整步」的情况：中止信号在每个 step 边界都会被检查一次。

### 2.4 已经发生的事全部留着

停止**不是撤销**：

- 时间线上这一轮已产出的消息、工具调用、文件改动徽标全部保留，末尾多一条中性的「**已停止**」标记（不是红色报错——这是用户自己按的，不是故障）。
- 刷新页面后看到的历史和停止前一致（这一轮照常落进[账本](../../terms.md)）。
- **文件改动不回滚**。agent 已经改掉、已经提交的东西就是改掉了；要退回去用 git（分支还在，见 [chat webapp](../../app/chat-webapp/feature.md)）。
- 沙盒不销毁、分支不删——下一条消息接着在同一个工作区跑。

### 2.5 刚发出就想停，也停得住（2026-07-27 修）

发完消息立刻反悔（发错了、想改措辞、点错了会话），点停止**就是有效的**。

这件事以前是坏的：那时点下去毫无反应，几秒后那一轮照样跑起来。原因是消息刚发出的头几秒服务端正在做准备工作（取沙盒、读 skill 等），那时它还不认这一轮存在，所以「停止」找不到可停的对象。现在从你点发送的那一刻起，这一轮就是可停的。

你会看到：

- 时间线上留着你刚发的那条消息，末尾一条中性的「**已停止**」标记——**和跑到中途按停止长得一样**。
- 这一轮**一个 token 都没花**，也没在沙盒里动过任何东西：它真的没开始。
- 想重发就直接再发一条，起新一轮。

一个诚实的说明：**这一档停止可能比跑到中途按停止慢**。准备工作里那几步（比如冷启动一个沙盒）一旦发出去就没法半路叫停，得等它自己回来，最坏情况几十秒。这段时间按钮是「停止中」，不会假装已经停了。

顺带一个小变化：这几秒的准备期内如果你又发一条消息，它会进**待发区**（以前会被服务端当成「另起一轮」处理，白等一次准备）。用 Alt/Option + Enter 想[插话](../../terms.md)也一样进待发区——那一轮还没建起来，插不进去，所以先给它排队，等它跑完自动接上。

### 2.6 停止之后照常继续

- 输入框可以直接发下一条消息，起新一轮。
- agent **记得**被停止的那一轮里已经完成的部分（它进了[模型上下文](../../terms.md)），所以可以说「刚才那步不对，改成……」而不用从头交代。

## 3. 范围与非目标

**做**：停止当前轮（服务端真中止）· 停止时清空待发队列 · 停止键（流式态的发送键）· 停止后账本照常收尾并标「已停止」· 停在审批卡片上也能停 · 幂等（连点无副作用）· 跨标签页一致。

**不做**（本期明确排除）：

- **撤销/回滚已做的改动**。停止只管「不再往下做」，不管「把做过的收回来」。回滚是 git 的事。
- **续跑被停止的那一轮**。停了就是停了，要继续就发新消息（新一轮）。
- **停止时自动让 agent 总结「我做到哪了」**。会多一次模型调用，与「停止 = 立刻不花钱」相悖。
- **Esc 等键盘快捷键**。停止是有后果的动作，本期只给一个明确的按钮，避免误触。
- **只停当前这一个工具调用、继续本轮**（「跳过这一步」）。那是另一件事，不在本功能内。
- **多用户共享会话时的停止权限**。当前一个会话只有 owner 一个人用。

## 4. 成功标准

1. 一轮跑到中途按停止：几秒内时间线停止增长、末尾出现中性的「已停止」标记，服务端日志确认没有新的模型调用。
2. 刷新页面后历史与停止前一致（已产出的消息、工具调用都在，末尾仍是「已停止」）。
3. 排 3 条消息后按停止：待发区清空，等一分钟确认没有任何一条被自动发出。
4. 停在审批卡片上按停止：卡片落成「已拒绝」，本轮随即结束，不用等审批超时（默认 4 分钟）。
5. 停止后立刻发一条新消息：正常起新一轮，且 agent 的回答体现出它记得上一轮做过的事。
6. 连点停止键 5 次：只有一次生效，界面不报错、不出现重复的「已停止」标记。
7. 另开一个标签页看同一个会话：那一轮也是「已停止」状态，输入框回到空闲形态。

新增（2026-07-27，对应 §2.5）：

8. **发一条消息后立刻（1 秒内）按停止**：那一轮不启动——服务端日志里没有任何模型调用；时间线上留着刚发那条消息 + 末尾「已停止」标记；刷新页面后一致。
9. 同样的操作**在冷启动沙盒的会话上做**（第一条消息）：按钮进「停止中」，等准备工作回来后落成「已停止」，期间不假装已停。
10. 发一条消息后立刻再发一条：第二条进待发区（不是又起一轮）；等第一轮跑完它自动接上。
11. 发一条消息后立刻用 Alt/Option + Enter 插话：那条进待发区，不留「待注入」的悬空回显。
12. **准备工作失败**（比如故意配错沙盒凭据）后再发一条消息：能正常起轮——不会因为上一次失败把会话卡在「一直有轮在跑」的状态里。
