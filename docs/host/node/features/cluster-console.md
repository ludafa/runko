# 集群控制台 — 功能手册

> 术语见 [术语表](../../../terms.md)（[集群控制台](../../../terms.md)、[节点下线](../../../terms.md)、[运维容器](../../../terms.md)）。
>
> **⚠️ 下线时「手上的活尽量干完」「下线期间给这个会话发新消息会被拒」这两条是过渡行为**（2026-09-25）：将改为把任务立刻交给别的节点接着跑，下线期间发消息照常有效，见[交权与任务迁移 · 功能](../../../logic/orchestration/features/handover.md)。
> 技术方案见 [cluster-console · 技术](../tech/cluster-console.md)，施工见 [cluster-console · 施工](../plans/cluster-console.md)。
> 建在[集群实验环境](./cluster-lab.md)之上。

## 一句话

在 chat 前端打开 `/console`，**一眼看到每个会话此刻在哪个节点上跑**；点一下「下线」，这个节点就不再接新流量，手上的活尽量干完，**2 分钟内自己退出**，到点没退就被强杀。

## 1. 要解决的问题

集群跑起来之后，有两件事现在只能靠敲命令、翻日志：

| 想做的 | 现在怎么办 | 难在哪 |
|---|---|---|
| 看某个会话在哪个节点上跑 | 进 Postgres 查 `agent_leases` 表，再拿主机名去 `docker ps` 里对 | 两步查询、手工对照，而且主机名是一串容器 id |
| 让一个节点退出（模拟发版、缩容） | `docker stop` | 它不知道「先别给我派新活」：nginx 照样往它身上发请求，用户会碰上一串 502 |

## 2. 给谁用

- **玩集群的开发者**：想看滚动发布时用户感受是什么样的——节点走了，正在聊的会话会不会断、断多久。
- **框架维护者**：[交权](../../../terms.md)只有在真节点退出时才现形，控制台让它一键可复现。

demo 项目，**不设管理员**：登录了就能用。

## 3. 用起来是什么样

### 3.1 打开

```sh
# 照常起集群（前端要连进来，所以把信任来源指到前端）
CLUSTER_CLIENT_URL=http://localhost:5273 pnpm --filter @runko-chat/node-server cluster:up
```

浏览器登录后，左侧栏点「集群控制台」，或直接访问 `/console`。

### 3.2 看到什么

```text
┌ 集群控制台 ─────────────────────────────────────── 每 2 秒刷新 ┐
│                                                                │
│  节点 1  ● 在线        会话 2    [下线]                        │
│    · 修一下登录页的样式        alice@example.com   心跳 1 秒前 │
│    · 帮我写个 README          bob@example.com     心跳 0 秒前 │
│                                                                │
│  节点 2  ◐ 下线中 1:12  会话 1                                 │
│    · 跑一下测试               alice@example.com   心跳 2 秒前 │
│                                                                │
│  节点 3  ○ 已下线              会话 0    [重新上线]            │
│                                                                │
│  没在任何节点上跑的会话不显示（空闲的会话不占节点）。          │
└────────────────────────────────────────────────────────────────┘
```

- **节点三种状态**：在线、下线中（带倒计时，从 2:00 往下数）、已下线。
- **会话挂在哪个节点下面** = 它此刻正在那个节点上跑一轮（持有它的[租约](../../../terms.md)）。空闲的会话不属于任何节点，所以不列。
- **心跳几秒前**：持有者多久前续过一次租约。超过十几秒还没更新，说明那个节点可能卡住了。

### 3.3 点「下线」之后发生什么

确认框写清后果：「这个节点将不再接新请求；正在跑的对话会马上交给别的节点接着跑，还在跑的命令留在这里跑完；2 分钟后进程还在就强杀。」

确认后，节点做的事就是[交权](../../../terms.md)（[交权 · 功能手册](../../../logic/orchestration/features/handover.md)），按时间顺序：

| 时刻 | 节点这边 | 用户看到 |
|---|---|---|
| 0 秒 | 收到关机信号，进入「下线中」 | 控制台上变成「下线中 2:00」 |
| 0 秒 | 新请求一律回 503，nginx 自动换一个节点重试 | **无感**：请求落到别的节点上 |
| 几百毫秒内 | 每份对话交给别的节点：模型正在输出 → 这半步扔掉由新节点重新生成；正在跑命令 → 命令留在这里跑完；正在等人 → [挂起](../../../terms.md) | 聊天页一秒左右自动重连，接着看新节点上的直播；刚才那半段字被重新生成的内容替换；跑命令的显示「工具正在收尾」 |
| 命令跑完 | 结果写库，通知接手的节点 | 命令结果照常出现，agent 接着往下干 |
| 没活了 | 进程自己退出 | 控制台变成「已下线」 |
| 120 秒 | 还没退就被运维容器强杀 | 同上；没写回结果的命令被记成「结果未知」交给 agent 判断 |

**下线期间给这个会话发消息会怎样**：照常有效。对话几百毫秒内就交给了别的节点，消息、停止、答审批都由新节点处理。

### 3.4 重新上线

「已下线」的节点旁边有「重新上线」按钮：运维容器把那个容器再启动一次。节点起来、健康检查通过之后，nginx 自然会重新给它派流量，控制台变回「在线」。

## 4. 范围与非目标

**做**：

- 节点列表 + 状态 + 下线倒计时；会话 → 节点的对应关系；每 2 秒刷新。
- 下线（HTTP 与 WebSocket 新流量都不再打到它）、对话交给别的节点、命令跑完再退出、到点强杀。
- 重新上线。

**不做**：

- **管理员权限**：demo 项目，登录即可用（用户的决定）。控制台会列出所有用户的会话标题——线上别这么干。
- **加减节点**：副本数还是 `cluster:up` 的 `CLUSTER_REPLICAS` 说了算，控制台只能让已有节点下线/上线。
- **单进程跑法（`pnpm chat:server`）下的下线**：没有运维容器，控制台只读（能看会话，下线按钮置灰，并说明原因）。
- **在[多副本验证环境](../../../terms.md)（`docker/compose.yml`）里用**：那套三个副本是写死的，不接运维容器。

## 5. 成功标准

1. 三副本集群，节点 A 上正在跑一轮；点 A 的「下线」：
   - 这一轮**不中断**：在别的节点上接着跑完，账本里没有「已中断」；
   - 下线期间反复刷新页面、发新会话，**没有一个请求落到 A 上**，也**没有一个请求报错**；
   - A 很快退出（手上没有命令在跑的话是秒级），控制台显示「已下线」。
2. 节点 B 上正在跑一条命令；点 B 的「下线」：对话马上交出去，命令在 B 上跑完、结果照常出现，然后 B 退出。
3. 把命令的最长执行时间与强杀期限临时调短（环境变量，只为造这个场景），节点 C 上跑一条比强杀期限还长的命令；点 C 的「下线」：**到强杀期限被运维容器强杀**，那条命令在接手节点上被记成「结果未知」。
4. 「重新上线」之后，C 重新出现在列表里，新会话能落到它上面。
