# 中途插话与排队（使用手册）

> 相关：技术方案见 [../tech/steer-and-queue.md](../tech/steer-and-queue.md)，施工进展见 [../plans/steer-and-queue.md](../plans/steer-and-queue.md)。
> 依赖/延续：[chat 聊天 webapp](./chat-webapp.md)（消息发送、[直播流](../terms.md)、时间线渲染都在这里）· [UIMessage 单账本](./single-ledger.md)（[账本](../terms.md)只记已发生的事，排队消息刻意不进账本）。

这一份是**产品/使用视角**：解决什么问题、用户看得到什么行为、边界在哪。内部实现看 [技术方案](../tech/steer-and-queue.md)。

## 0. 一句话

agent 正在跑一[轮](../terms.md)时，用户还想说话，有两条路——**[排队](../terms.md)**（默认：不打扰这一轮，等它收尾后自动作为下一轮发出）与 **[steer 中途插话](../terms.md)**（显式：立刻插进当前这一轮）。排队的消息**存在服务端**，看得见、删得掉、清得空，刷新页面与换标签页都还在。

## 1. 要解决的问题

现状（本功能之前）：一轮还在跑时发消息，**一律** steer 插进当前轮，用户没得选，也没有提示说它去了哪。三个具体痛点：

1. **想说的是下一件事，却被塞进了这一件**。用户看着 agent 正在做 A，想排一句「做完 A 再做 B」，结果 B 被注入当前轮，模型可能当场改道去做 B，A 半途而废。
2. **发出去就收不回**。手快发错、发重复，没有任何撤回口子——只能等它生效再澄清。
3. **不知道它排在哪**。消息发出后在界面上没有位置（steer 的消息要等[核心循环](../terms.md) loop 真正注入才出现在时间线上），中间这段用户以为没发出去，于是再发一遍。

## 2. 用户看得到什么

### 2.1 默认：Enter 就是排队

一轮**正在跑**时，输入框里打字、按 Enter：

- 消息**不进当前这一轮**，落进**待发队列**，立刻显示在输入框上方的待发区里（「待发送 · N 条」）。
- 当前这一轮照常跑完，不受任何影响。
- 这一轮收尾后，服务端**自动**取队首起下一轮——用户不需要再按一次发送。队列里还有的继续排着，一轮一条依次发出。

一轮**没在跑**时（idle），Enter 和以前完全一样：直接起新一轮，没有队列这一步。

### 2.2 显式：插进当前这一轮

同一个输入框，两个入口走 steer：

- **Alt/Option + Enter**（快捷键）
- 输入框右侧的**插话按钮**（闪电图标，只在一轮进行中时出现）

插话的消息会在下一个 [step](../terms.md) 边界真正注入当前轮，随后以正常的用户消息出现在时间线上——和本功能之前的行为一致。

### 2.3 待发队列可管理

输入框上方的待发区：

- 逐条列出排队中的消息（按发出顺序），每条右侧一个 **×** 删除。
- 右上角**清空**，一次删光。
- 上限 **10 条**；满了再发会明确报错（「待发队列已满（最多 10 条）」），不会静默丢弃。
- 删除只对**还没发出**的消息有效——已经出队起轮的消息就是一条正常的用户消息了，删不掉（和「消息发出去就是发出去了」一致）。

### 2.4 队列是服务端的，不是这个浏览器标签的

- **刷新页面**：队列还在。
- **换标签页/换设备**打开同一个会话：看到同一份队列。
- 一个标签页里删了一条，另一个标签页**在这一轮进行中会同步看到**（走[直播流](../terms.md)）。
- **服务端重启**：队列还在（落库了）。但要注意——重启会中断正在跑的那一轮（这是 chat 应用[既有的取舍](./chat-webapp.md)，不是本功能引入的），所以队列会一直排到下一次有轮收尾时才继续发。

### 2.5 出错时不吞消息

自动出队起下一轮时如果起不来（沙盒恢复失败、模型配置问题等）：

- 这条消息**留在队列里**，不丢。
- 界面待发区显示一行提示（「上次自动发送失败，将在下一轮结束后重试」）。
- 用户手动发一条消息起新一轮，那一轮收尾后队列会继续自动排下去——自然恢复，不需要点重试。

## 3. 范围与非目标

**做**：排队/插话二选一、队列的查看与删除与清空、队列持久化与跨标签一致、自动出队起下一轮、队列上限。

**不做**（本期明确排除）：

- **编辑排队中的消息**。要改就删了重发——省掉「编辑到一半正好被自动出队」的竞态。
- **调整队列顺序**（拖拽排序）。先到先发。
- **排队消息里选 provider / 改模型**等每条独立参数。队列条目只有文本。
- **停止当前轮**。「停下现在这一轮」是另一件事（需要 loop 级取消能力），不在本功能内——已由 [停止本轮](./turn-abort.md) 单独实现（那一期按定案：停止时[待发队列](../terms.md)一并清空）。
- **多用户共享一个会话时的队列可见性/权限**。当前一个会话只有 owner 一个人用；队列条目已记录发起人 `userId`，为将来留好数据，但本期不做区分渲染。

## 4. 成功标准

1. 一轮进行中按 Enter，消息进待发区、当前轮的输出不受影响；该轮收尾后队首自动作为新一轮发出，时间线上顺序正确、不重复、不丢。
2. Alt+Enter / 插话按钮走 steer，行为与本功能之前一致（下一个 step 边界注入）。
3. 排队 3 条，删中间 1 条，剩下 2 条按原顺序依次发出。
4. 排队后刷新页面、或另开一个标签页，看到同一份队列。
5. 队列满 10 条时第 11 条被明确拒绝并提示，不静默丢。
6. 自动出队起轮失败时消息仍在队列里，手动发一条后能自然恢复排队推进。
