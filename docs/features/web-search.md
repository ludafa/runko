# 联网搜索（web search）· 产品文档

> 相关：[技术方案](../tech/web-search.md) · [施工进展](../plans/web-search.md) · [chat 应用（产品）](./chat-webapp.md) · [内置工具（产品）](./builtin-tools.md) · 术语见 [docs/terms.md](../terms.md)

## 1. 要解决的问题

chat 应用里的 [agent](../terms.md) 只看得见两样东西：[沙盒](../terms.md)里 clone 好的那个仓库，和模型自己脑子里的知识。后者有知识截止日期——问它「这个库最新版怎么用」「这个报错别人是怎么修的」，它要么按旧版本答，要么直接编一个看起来合理的 API 出来。用户拿到的是一份读着顺、跑不通的代码。

**联网搜索**给它第三样东西：查网的能力。让「我不知道」变成「我去查」。

## 2. 使用场景

三类，都来自 chat 应用的日常：

1. **查最新用法**——「帮我把这个项目的 xxx 升到最新版」。agent 先搜一遍这个库当前的 API 和迁移说明，再动代码，而不是照着两年前的记忆改。
2. **查报错**——沙盒里跑构建挂了、报了一句陌生的错。agent 拿这句错去搜，找到成因再修。
3. **查事实**——「这个协议现在的推荐做法是什么」「这家的定价是多少」。属于讨论轮，不改代码。

## 3. 用户可见行为

- **谁来决定搜不搜**：模型自己。界面上没有搜索框，用户不用（也不能）手动触发一次搜索——你只管正常提问，agent 觉得需要就去搜。
- **看得见的东西**：对话流里出现一张工具卡片，名字是 `web-search`，跟 `bash`、`ask-user` 那些卡片长得一样。折叠时一行摘要，展开能看到它搜了什么词、拿回了哪几条结果（标题、网址、发表日期、摘录）。卡片右侧照常显示计时。
- **不需要审批**：这是只读动作——不碰仓库、不碰用户的 GitHub 权限，所以不弹审批卡片，直接跑。跟 `git push` 那类外发动作不是一回事。
- **失败了会怎样**：卡片标红显示失败原因（比如 key 无效、被限流、超时），这一轮不会因此中断——模型看得到失败原因，可以换个词再搜，或者直接说「我查不到，以下是我的判断」。

## 4. 怎么开启

在仓库根 `.env` 里填一个 [Exa](https://exa.ai) 的 API key：

```
EXA_API_KEY=your-key-here
```

**不填就等于没这个功能**：工具根本不会注册进 agent 的工具表，模型看不见它，也就不会尝试去调用（不会出现「调用了一个用不了的工具」这种失败卡片）。填了之后重启 chat server 即生效，无需改任何代码或配置。

Exa 按搜索次数计费，key 在服务端进程里，**不会进沙盒、不会出现在模型上下文里**——模型只能通过这个工具间接用它，拿不到 key 本身。

## 5. 范围与非目标

**这一版做**：一个 `web-search` 工具，输入一句自然语言查询（可选：要几条、限定内容类别、限定站点），输出若干条结果的标题 / 网址 / 日期 / 正文摘录。

**明确不做**：

- **不做单页正文精读工具**。Exa 另有 `/contents`、`/answer` 等端点，这一版只接 `/search`。agent 想读某个网页全文，走沙盒里的 `curl`（已有能力），不新开工具。
- **不做用户手动搜索入口**。界面上不加搜索框——这是 agent 的工具，不是用户的功能。
- **不做结果缓存 / 去重 / 配额管理**。每次调用即一次真实请求，按次计费；控成本靠 agent 自己少搜，以及默认只取 5 条。
- **不做多供应商切换**。只接 Exa 一家。工具对模型暴露的名字叫 `web-search` 而不是 `exa-search`，是给将来换供应商留的余地，但这一版没有切换开关。
- **不进 `@nimbo/*` 发布包**。这是 chat 应用自己的工具，SDK 用户不会因此多一个依赖（理由见[技术方案 §1](../tech/web-search.md)）。

## 6. 成功标准

1. 没配 `EXA_API_KEY` 时，chat 应用的一切行为与加这个功能之前**逐字节一致**（模型的工具表里没有它）。
2. 配了 key 之后，问 agent 一个它显然不知道的时效性问题（比如某个库的最新版本号），它会调 `web-search` 而不是硬编，且回答里带得出来源网址。
3. 搜索失败（key 错、限流、超时）时，这一轮不崩——卡片标红，模型继续把话说完。
4. 搜索结果不把上下文撑爆：默认 5 条、每条正文摘录截断，一次调用的输出量可控。
