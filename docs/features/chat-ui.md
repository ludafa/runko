# Chat 界面语言（产品视角）

> 相关：[chat 应用产品文档](./chat-webapp.md) · [技术方案](../tech/chat-ui.md) · [施工进展](../plans/chat-ui.md)
> 术语一律引用 [docs/terms.md](../terms.md)（本功能新增的界面术语已登记在「十一、界面语言」一节）

## 一句话

chat 页面的界面语言**建立在 [ai-elements](https://elements.ai-sdk.dev/) 上**——Vercel 官方的 AI 界面组件库，密度整体收到「sm 档」，让一轮十几个工具调用也能一屏看下来。

## 要解决什么问题

改版前的页面上，[推理](../terms.md)、工具调用、[审批卡片](../terms.md)、ask-user 提问、计划清单、文件改动——六类语义完全不同的东西全是手写的、长得差不多的圆角卡片；agent 正文没有容器、通宽排到 90+ 字符，反而是全页最难读的一段。

问题有两层：

1. **层级读不出来**：六类东西视觉权重相同，一轮十几个工具调用就把正文淹了。
2. **每一块都是自己造的轮子**：`Conversation`/`Message`/`Tool`/`Reasoning` 这些早在改版前就是「照着 ai-elements 抄一遍再改」（几个文件头部至今写着 "Adapted from AI Elements"），抄完就与上游断了联系——上游修的 bug、加的能力都拿不到。

## 给谁

盯着 agent 在自己分支上干活的开发者。他们的动作只有三个：**读**（agent 说了什么）、**扫**（它做了哪些事、花了多久）、**拍板**（允许 / 拒绝 / 回答）。

## 做法：装真的 ai-elements，而不是继续抄

每一块界面都换成官方组件，nimbo 特有的部分作为**薄封装**留在 `features/chat/components/` 里：

| 界面元素 | 用的组件 | nimbo 自己补的部分 |
|---|---|---|
| 消息流与自动贴底 | `Conversation` | — |
| 用户 / agent 消息、markdown | `Message` / `MessageContent` / `MessageResponse` | agent 侧撑满栏宽（装的是块级卡片，不是气泡） |
| 工具调用 | `Tool` / `ToolContent` / `ToolInput` / `ToolOutput` | 中文状态词、**工具计时条**、「等待中」这一档（官方没有） |
| [推理](../terms.md) | `Reasoning` | 中文文案（思考中… / 思考了 N 秒） |
| [审批](../terms.md) | `Confirmation` | 三值裁决按钮（允许 / 会话内都允许 / 拒绝），比官方的二值多一档 |
| 计划清单 / 文件改动 | `Task` | 勾选框、`+ / ~ / -` 前缀、图标（官方默认是放大镜） |
| [待发队列](../terms.md) | `Queue` | 「插进本轮」动作 |
| 输入框 | `PromptInput` | 插话按钮 + `⌥⏎` 键位；流式态发送键即[停止](../terms.md)键（见 [features/turn-abort](./turn-abort.md)） |
| ask-user 提问 | *（ai-elements 没有对应件）* | 用同一批基元（`Alert`+`Button`+`Input`）自己拼，与审批卡片同族 |

### 密度：sm 档

ai-elements 出厂密度是给「一屏几条消息」的通用聊天场景设的。nimbo chat 一轮动辄十几个工具调用，出厂间距下一屏放不下几行。所以在**组件本体**里统一收一档：消息间距 `gap-8→gap-4`、工具卡片内边距 `p-4→p-2.5`、用户气泡 `px-4 py-3→px-3 py-2`、输入框最小高度 `min-h-16→min-h-10`。

收在组件里而不是每个调用点覆盖 `className`——后者会让密度散落各处，下次重新 `add` 组件就全丢了。

## 用户可见的行为变化

- **[中途插话](../terms.md)从一枚闪电图标变成带字的按钮**：输入框工具条上是 `⚡插话 ⌥⏎`（只在一轮进行中出现）。
- **一轮进行中，发送键是方块[停止](../terms.md)键**（[features/turn-abort](./turn-abort.md)）：点它停止这一轮（待发队列一并清空）。排队因此只剩 Enter 一条路，placeholder 里明说；一轮结束后按钮回到发送键。停止后时间线末尾是中性的「已停止」标记，不是红色报错——那是用户自己按的。
- **待发队列里的每条消息多了「插进本轮」**：改主意时不用再删了重发。它把那条消息从队列取出、立刻注入当前这一轮。
- **插话立刻可见**：点了插话，消息马上以「插话 · 待注入」的压暗形态出现在时间线末尾。它的真实注入点是 agent 的下一个 step 边界，可能要等几十秒——在那之前界面上什么都不发生的话，用户会以为按钮没生效。等真正注入了，它就变成一条正常消息。
- **聊天页占满整屏、会话侧栏可收起**：原来整个应用被夹在 1152px（`max-w-6xl`）居中，1440px 屏上两侧各空 144px，而中间的代码块和宽表格反而在横向滚动。现在聊天页满宽；左侧会话列表换成可收起的侧栏，点顶栏左端的把手（或按 `⌘B` / `Ctrl+B`）整条滑出，读长 diff、宽表格时把那 220px 让给内容。**收起状态刷新后保持**（存 cookie）。Notes 那类读文档的页面不变，仍夹在 6xl 内——满宽的长文本行反而难读。
- **新建会话改成弹窗**：侧栏顶部常驻的「标题输入框 + provider 切换」先收成一枚 `＋ 新会话`，点开的是一个弹窗而非侧栏内嵌表单——侧栏只有 220px 宽，表单挤在里面同样局促。弹窗里控件回到正常尺寸，两个 provider 各带一句话说明（Vercel「按名字恢复，快照到期前一直在」/ E2B「空闲自动暂停，下条消息唤醒」），底部是「取消 / 建会话并开分支」。提交即关，等待反馈交给会话区（见下条）。
- **建会话的等待反馈**：点「建会话并开分支」后**不等服务端返回**，会话区当帧就换成准备中视图——四个阶段（创建沙盒 / 拉取仓库代码 / 安装技能 / 准备工作分支）逐步点亮、当前阶段带已等待秒数，侧栏顶部同时占出这条会话的位置。建一个会话要开[沙盒](../terms.md)、clone 仓库、装 skill、建分支，实测 9 秒起（provider 与仓库大小都会拉长），此前这段时间里界面只有一枚变灰的按钮，静止到让人以为没点上。**阶段是按实测耗时估的、不是真进度**：服务端目前是一个同步请求、没有进度可推，所以刻意不画百分比、不给「还剩 N 秒」，最后一个阶段停在原地直到真的返回；拖过 20 秒会明说「比平时久一些」。
- **建会话失败终于看得见**：失败时显示错误原因 + 「重试」（沿用原输入重发）/「返回」。此前失败是完全静默的——请求抛错被吞掉、按钮弹回可点、界面毫无变化。
- **会话列表去掉徽标**：`active/sleeping/expired` 三枚英文徽标换成一个状态点，provider 并入分支行尾。
- **会话功能条压成一行，主位给会话标题**：`状态点 + 会话标题` 居左，`分支名（缩写）+ 复制 + ⓘ详情` 靠右，底部一条细线与对话流分开。曾经反过来试过——分支名当 H1、标题降为小字，理由是「分支才是这一页真正在生产的东西」。那个理由只对**有语义的分支名**成立；这里的分支名是 `nimbo/chat-<uuid>`，没人读得出也记不住，只会被复制，占着最大的位置就是把版面给了噪音。现在分支名显示成 `nimbo/chat-8430…5fb1`（**中间**省略，保留尾号——那是两条会话分支唯一的区别），hover 出 tooltip 说明「这个会话的 git 分支」并给全名，复制的始终是全名。
- **「会话详情」弹窗（两个 tab）**：点功能条右端的 ⓘ 展开。
  - **详情**——完整分支名、仓库、沙盒 provider、状态、创建/最后活跃时间。仓库与 provider 此前常驻功能条：前者来自全局 `GITHUB_REPO`、每个会话完全相同、零区分度，后者建会话时选定后不再变。都属于「偶尔要查」而非「一直要看」，常驻只会挤掉标题的位置——收起来，不是丢掉。（不重复会话标题——它在功能条上已是主位；也不显示沙盒名——那与分支名只差个前缀，是实现细节。）
  - **统计**——**整个会话**至今的用量：轮数（含失败几轮）、总耗时与工具/agent 拆分、输入/缓存命中/输出/共计 tokens。与消息末尾那枚「统计」互补：那个答「这一轮花了多少」，这个答「这个会话花了多少」。还没跑完过一轮时给一句话，不是一屏 0。
- **顶栏换成自己的身份**：`nimbo / chat`（原来是脚手架留下的 `hono · mono`）。
- **空态改写**：「还没有消息」→「这条分支还没有指令」，并说明下一步做什么。

## 范围与非目标

- **以改呈现为主**：发送/排队/插话/审批/回答的语义与快捷键一律不动。交互增量只有四处，都是改版过程中暴露的反馈缺口：新建会话表单折叠、分支名点击复制、待发消息「插进本轮」、插话的「待注入」回显。
- **不改色板**：沿用 shadcn 默认中性色板与圆角，让 ai-elements 保持它原本的样子。
- **不做移动端**：沿用 [chat-webapp](./chat-webapp.md) 的非目标，但布局在窄屏不塌、可用。
- **登录 / 注册 / Notes 三页不在范围内**。

## 成功标准

1. 一屏能看下「一段正文 + 三四个工具调用」，不用滚动就能判断 agent 在干什么。
2. 深色 / 浅色两套下对比度均达 WCAG AA。
3. 键盘可达：工具卡片、审批按钮、composer 都有可见焦点环。
4. `prefers-reduced-motion` 下无位移动画。
5. 现有 web 测试全绿。

## 怎么看效果

开发期访问 `/design`——**设计工作台**：不连服务端、不需要登录，用固定假数据把每一档状态铺在同一屏上。生产构建里这条路由不存在。
