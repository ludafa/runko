# Turn Checkpoint 与沙盒保活（使用手册）

> 相关：[技术方案](../tech/turn-checkpoint.md)，[施工进展](../plans/turn-checkpoint.md)。
> 依赖/延续：[chat 聊天 webapp](../../../ingress/features/chat-webapp.md)（turn 收尾边界、时间线渲染都在这里）· [UIMessage 单账本](./single-ledger.md)（快照的 `lastSeq` 直接对齐[账本](../../../terms.md) `seq`）。
>
> **状态：方案定稿待施工**（2026-07-14 随 P13 持久化分析逐项讨论定案；本功能尚未施工，下面描述的是承诺给用户的对外行为）。

这一份是**产品/使用视角**：这个功能给用户和接入方解决什么问题、看得到什么行为、怎么开关、怎么判断它是否达标。内部怎么实现看 [技术方案](../tech/turn-checkpoint.md)。

## 0. 一句话

两个正交机制、一次施工：

1. **[代码快照（checkpoint）](../../../terms.md)**——每[轮](../../../terms.md)结束把[工作区](../../../terms.md)完整状态存到用户仓库的一个[快照引用（checkpoint ref）](../../../terms.md)里，[平台快照](../../../terms.md)过期不再等于「丢工作」，只等于「恢复慢一点」。
2. **[保活](../../../terms.md)（keepalive）**——[沙盒](../../../terms.md)的[存活时长](../../../terms.md)是「租期倒计时」，跑命令不续命；[turn](../../../terms.md) 进行中主动续命，让长任务不再干到一半被平台回收，同时修掉现有续期动作乱烧钱的 bug。

## 1. 要解决的问题

### 1.1 代码快照解决的问题

现状：agent 在沙盒里改的文件，如果还没 `git push`，全靠 Vercel 的[平台快照](../../../terms.md)兜底。平台快照是**加速缓存**、会过期——一旦过期，沙盒重建就只能重新 clone 分支，agent 这一段没 push 的改动（含未 commit 的改动、新建文件）全部消失。用户的感受是「我明明让它写了半天，怎么回来全没了」。

代码快照把这段工作搬到**持久层**：每轮收尾把工作区完整状态推到用户仓库的一个隐藏 git 引用（`refs/runko/wip/<sessionId>`），不依赖平台快照是否还在。

### 1.2 保活解决的问题

现状两个毛病：

- **长任务中途暴毙**：Vercel 沙盒的时效是租期倒计时，跑命令**不算续命**。一轮跑 10 分钟、20 分钟的设计任务，超过 5 分钟（默认 `SANDBOX_IDLE_TIMEOUT_MS`）就可能干到一半被平台回收。
- **续期动作乱烧钱**：现有的续期动作（`touch`）每来一条消息就盲目「加 5 分钟」，是**加时**不是**补足**——高频对话后沙盒会多活几十分钟，白计费，还可能撞套餐总时长上限。

保活把续期改成「补足到还剩 X 分钟」的语义：turn 进行中由一个心跳定时器盯着水位、不够就补，够了就什么都不做。

## 2. 用户看得到什么

### 2.1 平时无感

代码快照平时用户和模型都察觉不到：

- **不动会话分支的提交历史**——快照不 commit 到你的分支，agent「不主动 commit」的承诺不被破坏。
- **GitHub UI 看不到**——快照存在 `refs/runko/*` 下，不在 `refs/heads/*` 分支命名空间里，GitHub 网页、PR 列表都不显示，也**不触发 CI / preview 部署**。
- **仓库管理员可见但不算后门**——`git ls-remote` 能列出这些引用（如实记录，不藏）。

保活平时也无感：turn 一结束心跳立刻停，用户离开 5 分钟后照常[休眠](../../../terms.md)、照常存平台快照，唤醒体验完全不变。

### 2.2 沙盒被重建时会诚实告诉你

当沙盒确实被平台回收、需要重建时，时间线上会出现一条系统事件 `sandbox.recreated`，**如实说明恢复到了什么程度**：

| 恢复级别 | 含义 | 用户感受 |
|---|---|---|
| `wip` | 平台快照没了，但从代码快照**完整还原**了工作区 | 未 push 的改动都回来了（以未提交改动形态） |
| `branch` | 代码快照也取不到，只**恢复到了会话分支**的最新提交 | 分支上的东西在，本轮之后未 push 的工作丢了 |
| `fresh` | 分支从未 push 过，**全新**签出 | 全新工作区 |

同一份信息也会在下一轮**注入给模型**，让人和模型都不被误导——不会出现「模型坚信改过、其实没改」的情况。

### 2.3 对外 API 视角

- `sandbox.recreated` 是一条落[账本](../../../terms.md)、可[回放](../../../terms.md)的系统事件，字段 `{ recovery: 'wip' | 'branch' | 'fresh', checkpointTurn?, stateTurn }`，任意 chat 客户端都能在时间线里渲染成一条简单系统条目。
- 审批的 240 秒超时（`CHAT_APPROVAL_TIMEOUT_MS`）**语义不变**——保活接管了「赶在沙盒死前了结」的保命职责后，审批超时回归纯产品决策（人多久不理算放弃），数值不动。

## 3. 怎么用（接入方开关）

两个新增环境变量（写进 `.env.template`，注意该文件受权限保护、需人工编辑）：

```
CHAT_CHECKPOINT_MODE=wip               # wip（默认，启用 turn 快照）| off（完全关闭，回到纯平台快照）
SANDBOX_TURN_KEEPALIVE_MAX_MS=1800000  # 单轮保活上限，默认 30 分钟（超限停止续命，让倒计时自然终结失控任务）
```

- 想彻底关掉代码快照（比如宿主不接受向 origin 写引用）：`CHAT_CHECKPOINT_MODE=off`，回到现状纯平台快照。
- 心跳间隔**不单开旋钮**，恒为 `SANDBOX_IDLE_TIMEOUT_MS / 2`（默认 150 秒），减少配置面。

## 4. 范围与非目标

### 代码快照

- **不备份 `.gitignore` 覆盖的产物**（`node_modules`、构建缓存等）——可重建，不进快照。
- **本期不做快照浏览 / 回滚 UI**。快照按轮链式保留（每轮一个提交、父子相连），「回滚到第 3 轮工作区」这类功能有了现成原语，但 UI 留给以后。
- **不承诺恢复未 push 的 commit 历史**：agent 在沙盒里做过但没 push 的**提交记录**不保证回来——这些提交里的**文件内容**在快照树里，会以未提交改动的形态回来（内容不丢，提交记录丢）。

### 保活

- **不改休眠 / 唤醒语义**。
- **不给失控任务无限续命**——有单轮上限（`SANDBOX_TURN_KEEPALIVE_MAX_MS`），到点停止续命，让倒计时自然收尾。

## 5. 成功标准（真机验收）

- **长 turn 不死**：一轮跑超过 5 分钟的任务不再中途被平台回收。
- **快照可见性正确**：快照引用在 origin 上 `git ls-remote` 可见，但 GitHub UI 看不到、不触发 CI。
- **重建走 wip 还原**：手动删掉平台快照后重建，能走「代码快照还原」路径把工作区找回来。
- **恢复级别如实呈现**：`sandbox.recreated` 事件上报的 `recovery` 级别与实际恢复程度一致，时间线与模型注入都不误导。
- **不多烧钱**：高频对话后沙盒不再多活几十分钟——续期是「补足」不是「加时」，水位恒定。
