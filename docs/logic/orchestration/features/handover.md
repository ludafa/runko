# 交权与任务迁移 — 功能手册

> 相关：[技术方案](../tech/handover.md) · [施工](../plans/handover.md)。
> 依赖/延续：[优雅关闭与崩溃恢复](./graceful-shutdown.md)（本功能取代它「关闭时一律中止」的行为）· [挂起与恢复](./suspend-resume.md) · [多副本部署](../../../host/node/features/multi-replica.md)。
> 术语见 [术语表](../../../terms.md)。

## 一句话

**发新版本、缩容、换机器的时候，正在跑的 agent 任务自动搬到另一个节点上接着跑。** 用户不会看到报错，也不会看到「这一轮已中断」；就算用户已经关了页面，任务照样跑完。

## 1. 要解决的问题

多副本部署时，发布新版本要一台一台替换旧节点。今天旧节点下线时：

| 下线那一刻 | 今天的结果 |
|---|---|
| 这一轮在等人答审批 | ✅ 挂起，人回来在任何节点上都能答 |
| 这一轮在跑模型或跑命令 | ❌ **直接中断**，界面显示「服务重启，这一轮已中断」，要用户重发 |
| 有排好队的消息 | ❌ 留在库里没人发，要等用户再发一条才动，而且顺序会颠倒 |
| 用户正好在这几秒里点了「允许」 | ❌ 显示成功，但什么都没发生 |
| 用户正好在这几秒里发了消息 | ❌ 收到「服务正在重启，请稍后重试」 |

agent 的一轮经常要跑好几分钟。发布一次，所有正在跑的任务都被打断一次；用户重发之后还可能落到另一台还没替换的旧节点上，**再被打断一次**。

## 2. 用户看到什么

### 2.1 正在看着的用户

- 直播流会断开一下，然后**在一秒左右自动连上**，界面不弹任何提示。
- 如果那一刻模型正在输出，刚才流出来的半段字会被替换成重新生成的内容。
- 如果那一刻正在跑一条命令，界面显示「工具正在收尾」，命令跑完后结果照常出现，然后 agent 接着往下干。
- 这段时间里发消息、点停止、答审批，都照常有效。

### 2.2 已经关掉页面的用户

任务照常跑完。回来打开页面，看到的是一轮完整的结果；配了推送通知的，照常收到「完成了」或「等你答复」的通知。

### 2.3 什么时候用户还是会有感觉

| 情况 | 用户感觉到的 |
|---|---|
| 模型输出到一半被搬走 | 半段字被替换（多花一点 token，但看不到报错） |
| 单副本、先停旧的再起新的 | 新进程起来之前的那几秒连不上；直播流自动重连能盖住，发消息要客户端自动重试 |
| 旧节点在命令收尾期间真的崩了 | agent 会被告知「执行这条命令的节点下线了，结果未知」，由它自己判断要不要再跑一次 |

## 3. 构建者要做什么

| 要做的 | 为什么 |
|---|---|
| 配一个**工具最长执行时间**（缺省 2 分钟） | 旧节点最多等这么久就能退出。超过它的任务改成「后台起任务、返回任务 id、之后再查」 |
| K8s 用**先启再停**（`maxSurge ≥ 1`、`maxUnavailable: 0`） | 只有这种顺序能做到用户完全无感 |
| **宽限期**（`terminationGracePeriodSeconds`）不小于「工具上限 + 30 秒」 | 旧节点要活到命令跑完 |
| **mesh 的 sidecar 要撑到进程退出**（原生 sidecar，或调长它的退出等待） | 旧节点收尾时还要连数据库、连沙盒 |
| 发布流水线注入一个**每次发布都递增的序号** | 框架靠它挑「比自己新」的节点接手，回滚也要递增 |

## 4. 范围与非目标

**做**：按阶段交权（模型输出重来、工具在旧节点跑完、等人照旧挂起）· 指定节点接手 · 只挑更新的版本 · 交接完主动让浏览器重连 · 兜底的定时回捞 · 浏览器的快速重连。

**不做**：

- **命令收尾期间的实时输出**：命令跑完后结果一次性出现。
- **进程被强杀那一刻正在跑的命令**：结果只能记成「未知」，这是命令不能保证幂等的代价。
- **「过一会儿再查」的定时唤醒**：超长任务改异步之后，这一条单独做（见[技术方案 附录 C](../tech/handover.md#附录-c-后续工作)）。

## 5. 成功标准

1. **先启再停，三个节点滚动发布一轮**：发布期间持续有会话在跑模型、跑命令、等人、排队。发布结束后，没有一个会话出现「已中断」，没有一个请求拿到 503，账本序号不重、不漏。
2. **迁移次数**：先启再停时每份对话最多迁移一次；先停再启分批时最多两次。
3. **命令不被切断**：一条跑 90 秒的命令在第 10 秒赶上下线，它完整跑完，agent 拿到的是它的真实输出。
4. **关掉页面也跑完**：用户发完指令就关页面，任务在发布期间被迁移，最后完整结束。
5. **重连够快**：浏览器从断开到在新节点上收到第一帧，先启再停时在 2 秒以内。
6. **兜底**：让接手节点在答应之前故意挂掉，10 秒预留过期后，定时回捞把这份对话接走并跑完。
7. **同批下线**：先停再启分批时，两个同批节点互相挑中对方，接手方拒绝，对话最终落到存活节点上。
