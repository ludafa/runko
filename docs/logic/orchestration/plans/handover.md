## 各阶段

### H0 · 顺手修掉的小缺口

与主线无关，可以先做（技术方案 §3.2 的 G4、G5）：

- web 的 `turn-marker.tsx` 文案常量对齐 `@runko/agent` 的 `ABORT_REASON_SHUTDOWN`，并补一条防漂移的测试。
- 中止路径也把还没交给模型的插话转进待发队列（今天只有挂起时转）。

原来这里还有一条「进程退不掉」的兜底（G6），main 上的节点下线已经基本修掉，不再单列。

### H1 · core：交权信号

- `TurnOptions` 在 `signal`（中止）之外加一个交权信号。
- 语义：模型输出段收到它 → 掐断模型流、**把这半步从本轮消息里去掉**；工具段收到它 → **不动工具**，但也不等工具结果，本轮带着悬空的调用以「已交权」收尾，并报出哪些调用还在跑。工具的 promise 交给调用方继续持有。
- 验收：两段各一条用例；中止信号的既有行为不变。

### H2 · 归属仲裁：租约预留 + 节点登记表

- 租约行加 `reserved_for` / `reserved_until` / `awaiting_takeover`；`Grant` 加「放手并预留给某节点」；`acquire` 在预留期内只放行被预留者；`listStale` 与定时回捞只看「预留过期或无预留」。
- 新表 `agent_nodes`：登记、心跳、改状态、按「序号更大 → 同序号」挑候选。
- 四档库（Kysely 三方言 + Mongo）同步实现；`@runko/conformance` 加用例：预留期内只放行被预留者 · 预留过期退化成没人持有 · 预留与接管阈值互不干扰 · 挑候选时同批节点排在更新版本之后。
- 验收：四档库在真库上跑绿。

### H3 · 轮编排：按阶段交权

- `shutdown()` 改成：登记表里标成 `leaving` → 挑接手节点 → 对每份对话按阶段收尾（技术方案 §6 那张表）→ 预留 → 调宿主给的「请接手」回调 → 等工具收尾 → 返回。
- 工具收尾：登记记录、跑完写结果、查停止标记、截止时间到了由持有者写「未知」。
- 接手入口 `runtime.takeOver(conversationIds)`：逐个抢归属，按账本末尾决定接下来做什么（技术方案 §7.5）。
- 一个都挑不到时标待接手；`recover()` 同时扫待接手。
- **删掉等待窗口**：`createAgentRuntime` 的 `shutdown.finishWindowMs`、`shutdown()` 的同名参数、`ShutdownResult.finished`，以及它们的测试（`shutdown-finish-window.test.ts`）。不经过废弃期；changeset 标 **major**，说明里写清「节点下线改用按阶段交权，不再有等待窗口」。
- 验收：五个阶段各一条用例；附录 B 的 P1–P3 改写成正式用例并跑绿。

### H4 · 定时回捞

- 可配间隔，缺省 10 秒；只碰「没人持有、无有效预留、但有活没干完」的对话。
- 持久化接口要加一个跨对话的查询（「有活没干完的对话」）；Durable Object 那一档用 alarm 实现，不走这里。
- 验收：接手节点故意挂掉，预留过期后被回捞接走。

### H5 · 工具最长执行时间

- `AgentRuntimeOptions` 加 `toolTimeout`（缺省 `"2m"`），平时与交权时都生效。
- 验收：超时的工具被终止，模型拿到的结果说清原因。

### H6 · 接入层

- node-server：`POST /internal/takeover`（带 `RUNKO_PEER_TOKEN`）；登记本节点；SIGTERM 处理改成调新的 `shutdown()`；退出条件 = 没有工具在跑且没有连接，加硬上限；启动时先监听、再扫待接手。
- 直播流加请重连帧；非本节点持有的转发流在 SIGTERM 后直接关。
- web：收到请重连帧走快速重连（200～300 毫秒一次），重连后整体替换草稿。
- **删掉等待窗口的接线**：`index.ts` 的 `SHUTDOWN_FINISH_WINDOW_MS`、集群 compose 里对应的配置；`offline.ts` 的闸门不再放行转发来的请求（交接几百毫秒就完成，之后没有请求需要转给旧节点）。
- 验收：node-server 与 web 各自的测试跑绿；openapi 与前端 client 重新生成。

### H7 · 验证环境与验收

- [集群实验环境](../../../host/node/features/cluster-lab.md)加两个场景：先启再停滚动三节点、先停再启分批。发布期间持续有会话处在五个阶段中的某一个。
- 闸门不再放行转发来的请求（H6 已改），所以验证环境能复现「入站随 SIGTERM 一起关」（技术方案 F1）。
- 断言按功能手册 §5 的七条，一律落在账本、租约表、收尾记录上。
- 文档：[集群控制台](../../../host/node/tech/cluster-console.md)三份文档里的等待窗口改写成交权；术语表删掉「等待窗口」词条。

### 集群端到端的场景与结果（2026-09-25）

`test/e2e/cluster-handover.e2e.test.ts`，演示模型 + 本地沙盒，三个老副本（发布序号 1）换成三个新副本（`node-next`，发布序号 2）：

| § | 场景 | 断言 | 结果 |
|---|---|---|---|
| 1、2、4、5 | 先启再停滚动发布：模型输出、跑命令（没人看着）、等人、排队四份对话 | 没有「已中断」；发布期间经 nginx 的请求没有一个失败；账本序号不重、升序；每份对话最多迁移一次；看着的那一份重连用时 < 2 秒 | ✅ 重连 16 毫秒 |
| 3 | 同上，命令 `sleep 20` 在第 4 秒赶上下线 | 命令在旧节点上完整跑完，结果（`tool-finished`）出现在账本里，新节点接着跑完 | ✅ 旧节点等命令跑完约 12 秒后自己退出 |
| 7 | 先停再启分批：持有者与另一个副本同时下线 | 对话落到第三个副本上，没有「已中断」 | ✅ |
| — | 单副本先停再启 | 挑不到接手节点 → 标待接手 → 同一容器重启后接着跑完，只迁移一次 | ✅ |
| 6 | 接手节点答应后挂了 | 容器里造不出确定的时序，由 agent 单测钉住（预留期内回捞不碰它，过期后被接走） | ✅（单测） |

`cluster-console.e2e.test.ts` 按交权改写后 5/5；`cluster.e2e.test.ts` 8/8、`lab.e2e.test.ts` 9/9 不退化。

**浏览器实测**（agent-browser，手动集群 `runko-cluster` 已用新代码重建）：长回复进行中从控制台下线持有它的节点 → 2 秒内持有者换到别的节点，页面上半截文字被清掉、新节点重新生成，最后账本是「用户 → 已交权 → 完成」，页面没有任何「中断 / 已停止」，被下线的节点退出码 0。

**实测时修掉的两处实验环境问题**（nginx）：节点刚退出时 Docker 域名缓存里的旧地址会让连接挂到连接超时——`proxy_connect_timeout` 2 秒 → 500 毫秒、`resolver valid` 5 秒 → 2 秒（否则重连要白等 2 秒）；滚动发布时新老副本同时在线，`proxy_next_upstream_tries` 3 → 6（否则几次都挑中刚退出的节点，客户端拿到 504）。
