# 归属仲裁机制 — 使用手册

> 相关：[技术方案](../tech/arbitration-impl.md)，架构总纲 [功能](../../../architecture/features/agent-kernel.md) · [技术方案](../../../architecture/tech/agent-kernel.md) §5。
> 宿主层那三样可替换能力：[沙盒](../../../host/contract/features/sandbox.md) · [持久化](../../../host/contract/features/persistence.md) · [流分发](../../../host/contract/features/stream-fanout.md)。
> 依赖/延续：[优雅关闭与崩溃恢复](../../orchestration/features/graceful-shutdown.md)（[交权](../../../terms.md)的落地）。
> 术语：[归属仲裁](../../../terms.md) · [归属仲裁机制](../../../terms.md) · [独占](../../../terms.md) · [租期标识](../../../terms.md)。

## 0. 一句话

**保证同一份对话，同一时刻只有一个执行在跑**——单进程下是内存里一个 Map，多进程下是数据库里一张租约表，Cloudflare Durable Object 上什么都不用做。

## 1. 解决什么问题

同一份对话不能同时跑两个执行，两个理由：

- **记录是共享的** → 两个执行同时跑，各自看到的历史会打架；
- **能动手的地方（沙盒）是共享且有状态的** → 两个执行同时跑，互相踩文件。

所以「[独占](../../../terms.md)」不是为多机部署额外加的，**是从这两条推出来的必然要求**。单进程时它同样成立，只是内存里一个 Map 就满足了，看不出来而已。

这一步把两件事分开了：

| | 什么 | 变不变 |
|---|---|---|
| **要求** | 「我需要独占这份对话」 | **永远成立**，属于[逻辑层](../../../terms.md) |
| **机制** | 「怎么保证独占」 | **是部署形态的函数**，属于[宿主层](../../../terms.md) |

本文讲的是**机制**那一半。

## 2. 三种实现，按部署形态挑

| 部署形态 | 用哪种 | 装什么 |
|---|---|---|
| 单进程（本机 CLI、单个 Node 服务） | 内存里一个 Map | **什么都不用装**（`@nimbo/agent` 内置） |
| 多进程 / 多节点共享数据库 | 租约 + 心跳 + [租期标识](../../../terms.md) | `@nimbo/persist-*`（跟持久化同包） |
| Cloudflare Durable Object | **什么都不做**（平台保证单实例） | `@nimbo/durable-object` |

**租约版为什么跟持久化同包**：两者总是一起用——都要落库、共享同一个连接、共用同一套「比对后再写」的原语。分成两个包只会让人多装一个。

## 3. 你要知道的三件事

### ① 多节点下，它保证不了独占——只能「安全地失败」

这不是实现偷懒，是分布式系统绕不过去的一条：**你没法知道远处那个节点是死了，还是只是联系不上。** 两者从外面看一模一样（心跳都停了），却要求相反的处置。

| 实现 | 独占是什么级别的保证 |
|---|---|
| 单进程 / Durable Object | **真保证** |
| **租约** | **尽力 + 可检测**——保证不了「不发生」，只保证「发生时被拦住」 |

**对你的影响**：租约版下，**一轮跑到一半可能被告知「你已经不是主人了」**，然后停下。这是正常路径，不是 bug。单进程版下这条路永远走不到，所以**单进程测试跑绿不代表租约版没问题**。

### ② 你要告诉框架「我在哪」

租约表里存一个 `holder`——一个**你自己定义的不透明字符串**（k8s pod 地址 / Fly machine id / 随便什么）。框架原样存、原样透传，不解释它。

它的用处只有一个：别人抢不到归属时，框架会告诉[接入层](../../../terms.md)「持有者是这个 `holder`」，**由你把请求转过去**。转发是你写的，不是框架做的。

### ③ 有人要腾机器时，框架会主动放手

滚动发布、缩容、`SIGTERM` 时会发起[交权](../../../terms.md)：

| 当时在干嘛 | 怎么处置 | 用户感觉 |
|---|---|---|
| **正在等人** | **[挂起](../../../terms.md)，无损**——落盘退出、释放归属，人回来在别的节点恢复 | 只多等几秒唤醒沙盒 |
| **正在干活** | 跑完当前这一轮就放手；超过宽限期则按[停止](../../../terms.md)收尾 | 顺利的话无感；超时则看到「已停止，请重试」 |

## 4. 范围与非目标

**不做的**：

- **不是分布式锁**，也刻意不这么叫。那个词暗示「拿到锁就安全了」，跟 §3① 直接打架。
- **不管跨会话的资源冲突**。独占是**按会话**保证的：本机 CLI 那档多个会话共用一个项目目录，那种冲突不在它职责内。
- **不替你转发**。框架给 `holder`，转发是[接入层](../../../terms.md)的活。
- **崩溃不恢复**。进程被强杀时走的是老路（补一条「已停止」），因为它没停在干净边界上。

**已定案**（2026-09-01，逐条理由见[技术方案 §8](../tech/arbitration-impl.md)）：

- **接口方法签名** —— `acquire` / `inspect` / `listStale` / `clearStale` + `Grant` 的
  `nextSeq` / `release`。注意**没有显式的「续期」方法**：心跳是实现内部的事，接口上看不见。
- **心跳 5 秒 / 判死 60 秒**（12 拍）。两头都往保守挪：心跳快让老持有者更快知道自己出局，
  阈值长让别人几乎不可能误接管。代价是崩溃后的接管延迟是 60 秒。
- **交权宽限期 15 秒**，与 `shutdown()` 复用同一个默认值。

## 5. 成功标准

1. 单进程下不装任何东西，行为与今天完全一致。
2. 换成租约版之后，**两个进程同时对一个会话起轮**，只有一个成功，另一个拿到 `holder` 能转发过去。
3. 杀掉持有者进程，另一个节点在超时后能接管；**被误判的老持有者的写入一律被拒绝**，不会写坏数据。
4. Durable Object 那档不需要租约表、不需要心跳，代码路径能干净地绕过去。
